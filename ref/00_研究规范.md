# AI产业链研究：研究规范

- 版本：v1.5；补充代表企业、技术栈、竞争与关键控制环节研究，2026-11-04。
- 范围：承接总纲v1.3的全部证据规则和P1案例反馈；后续操作方法在此维护。

## 0. 研究与报告分阶段

研究目标与范围由[分析总纲](./01_分析总纲.md)维护；执行入口见仓库根目录 [AGENTS.md](../AGENTS.md)；成稿的 Writing Style 和 Highlight 规则统一见[报告写作规范](./05_报告写作规范.md)。

研究阶段优先收集、验证与整理数据和案例，形成有来源、口径、解释、反证和待补证据的研究底稿。原始资料和模型沿用“数据/”，专题底稿沿用“专题/”，过程性记录沿用对应 REVIEW 目录；字段完整性和证据追溯性优先，不为成稿形式删减原始材料。

报告阶段使用已核验材料，围绕主问题组织“判断—证据—解释—含义”，执行报告写作规范。新成稿默认进入“报告/”，用户指定输出位置时按其要求执行；通过链接引用底稿，保留关键数字与判断条件。发现影响结论的新证据缺口时回到研究阶段补证。

研究验收检查证据、案例、模型与覆盖完整性；成稿验收检查论证、可读性、重点呈现及改写后的事实保真。两类检查分别记录；本文件既有证据和研究验收底线继续适用于研究阶段，研究验收通过不自动代表成稿通过。

## 1. 证据与分析规范

1. 优先采用财报、监管披露、官方产品与价格、技术论文、官方统计和有明确方法的行业研究。
2. 公司对自身业务的披露可用于核实产品和经营数据；其市场地位与性能宣传需要独立交叉验证。
3. 每项关键数据记录来源链接、发布日期、观测期、地域、单位、定义及必要限制。
4. 明确标注事实、估算、预测、分析判断和待验证假设。
5. 区分AI收入与总业务收入、AI数据中心与全部数据中心、计划产能与投产产能、签约与交付、调用量与付费收入。
6. 价格比较记录配置、精度、输入输出结构、延迟、缓存、折扣与时间，不只比较标价。
7. 模型与系统比较同时考虑质量、成本、延迟、可靠性和真实任务表现。
8. 不将数据缺失视为零，不以未经披露的分部利润填补分析空白。
9. 涉及快速变化的价格、政策、产品和产能时，在专题撰写时重新核实。
10. 涉及财务指标比较时，记录折旧政策、资本化政策、租赁及结构化安排的差异；跨公司比较前先说明适用准则与口径是否可比。
11. 分别标注关联关系、供应商融资、交叉投资和资金依赖，核查真实交付与终端使用；第三方交易也可能依赖供应商融资，关联交易也可能具有真实需求，不将融资安排自动等同于收入虚假。
12. 使用历史类比（如电信光纤过建、加密矿场数据中心转型、云计算早期折旧争议）时，说明可比与不可比之处，不直接套用结论。
13. 区分公开研究可得结论与客户尽调待核事项。合同原件、设备权属、流水、债务到期表、担保及抵质押登记等列为补充材料；明确每项材料用于验证什么判断。
14. 公司案例用于框架适用性验证；缺乏历史样本、评价时点和实际结果时，不称为回测。对不适配客户保留例外处理，不强行归类。
15. 银行产品匹配须考虑具体服务主体、业务资格、区域与客户准入、交易真实性及本行能力；通用研究不替代具体授信审批或对产品可开展性的核实。

### 代表企业、技术栈与关键控制环节

产业研究先解释产品如何工作、谁提供关键能力、客户为何选择或难以更换供应商，再分析这些条件如何影响收入、成本、投资和现金。适用于各产业专题；2026-11-04经用户确认先以CHIP试点，用户验收后再改写三篇INFRA，不将规范更新视为既有专题已完成补强。

1. **按同一功能选择代表企业。** 同时覆盖中国与美国的主要路线，记录入选理由、产品、客户任务及地域。保留中国台湾、韩国、欧洲、日本等关键供应节点，分别识别企业归属、制造所在地和许可管辖。不得以财报易得代替技术代表性，也不得把不同工艺或设备类型强配成直接竞争对手。
2. **把技术栈拆成可核查的交付层。** 从客户工作负载到芯片／硬件、内存与互连、编译器与运行时、算子库、框架适配及部署工具，说明各层功能、接口、提供者和外部依赖。具体分层随专题调整，首次出现的术语说明作用。
3. **比较客户真正面对的取舍。** 比较任务质量、吞吐和时延、内存、能耗、可靠性、可交付数量、迁移工作量及总使用成本。性能比较必须记录产品与软件版本、精度、稀疏性、模型、输入输出长度、批量、并行配置、系统规模和测量方法；条件不一致时只解释架构取舍，不制造统一排名。
4. **将“垄断点”落实为控制机制。** 逐项回答谁控制什么、客户为何难以绕开、控制通过何种接口／工具／认证／供应安排实现、替代方案是什么及何时可能削弱控制。区分独家供给、寡头供给、生态黏性、工艺认证、暂时产能瓶颈和政策许可；未经监管或司法认定，不将这些事实写成法律上的垄断结论。
5. **份额与不可替代性分别取证。** 份额必须有产品市场、地域、期间、分母及方法；缺少可靠份额时保留未知，不用高毛利、品牌影响力或供应承诺推定垄断。厂商文档可证明接口和产品范围，厂商性能与地位宣传需交叉验证，官方开源公告也不能单独证明迁移成本已经消失。
6. **按阶段记录替代进展。** 区分发布与路线图、可下载软件、客户测试、商用部署、批量交付和持续运行。研发完成、单算子适配、模型运行成功、整套训练稳定运行属于不同证据；记录仍依赖的工具、器件、产能及服务。
7. **每项控制力判断配置反证。** 寻找开放接口、多供应商实现、客户自研、定制芯片、真实迁移和替代供给；说明反证影响哪个任务或环节，既不把局部替代写成全栈替代，也不把高迁移成本写成永远不可替代。
8. **将研究证据落盘后再成稿。** 代表企业与技术栈矩阵、控制机制、来源定位、证据等级、适用范围、反证和未决问题存入对应数据目录并链接至专题底稿。新增定量指标使用独立且不冲突的ID，原值、单位、期间与衍生公式分开保留；报告仅选取能解释主线的部分。

CHIP试点以数据中心AI芯片为主线，重点研究NVIDIA、AMD、华为昇腾等路线，沿软件、互连、EDA/IP、制造、存储和封装追溯依赖；端侧作为补充。金融样本可以保留，但不能由特色工艺代工或汽车芯片替代先进数据中心计算路线的分析。

### P1案例反馈与数据落盘规范

P1总论及证据见[全球全景与商业关系](./03_全球全景与商业关系.md)、[来源与术语](./04_来源索引与术语表.md)和[数据包说明](./数据/P1/README.md)。本次示踪案例对后续研究增加以下约束：

1. 区分现金购建、非现金资产取得、租赁及供应商融资；经营现金流减现金购建仅为明确口径的分析指标，不自动称为跨公司统一自由现金流或完整偿债缺口。
2. “GPU租赁”等商业称呼不决定会计分类；算力服务、已识别资产控制权与租赁处理须根据合同及适用准则核查。
3. 数据中心面积利用率与GPU使用率分开；现金流比较先调整持续／终止经营和并表范围，未经审计业绩稿保留状态标识。
4. 分销及集成业务同时核查总额／净额收入、备货、供应商账期、验收及回款；集团数据不得自动视为纯AI数据。
5. 外部数据保存原始数值、单位、来源定位、观测期、范围、状态及限制；归一和衍生计算另存公式与输入ID。关系图的现金流、非现金股权、合同机制和战略说明分开，未提取金额不填零。
6. 本阶段完成公开证据层面的关系图谱；合同附件、流水和最终使用未核实部分保留为尽调缺口，不以框架完成代替逐笔真实性验证。

## 2. 通用数据字段与换算

## 字段和使用规则

原始指标字段：id（D编号）、source_id、entity、metric、period、raw_value、raw_unit、status、scope、locator、notes、normalization_multiplier、normalized_unit、currency。原始数字使用字符串，避免浮点数精度改变。归一值＝原值×换算因子；衍生C指标另保留input_ids、formula与source_ids。

来源字段：source_id、publisher、title、url、publication_date、coverage、source_type、limitations、accessed_on、access_status。发布日期只有年份的保留年份；查阅日不等于发布日期或统计期。

关系字段：edge_id、from、to、relationship、amount_metric_id、source_ids、period、evidence_level、limitations。金额为null意味着本次未提取可归属的金额，**不是零**。筹资净额不能分配给单一投资者；存货变动不能充作采购现金额；战略联系不画成实际资金汇款。

## 单位与边界

- 美元百万元×0.001＝十亿美元（USD billion）；1十亿美元＝10亿美元。主文部分采用亿美元，转换关系明确，数据台账保留十亿美元便于原表核对。
- 人民币百万元×0.01＝亿元；人民币千元×0.00001＝亿元；人民币元×0.00000001＝亿元。
- 1亿千瓦时＝0.1 TWh；1000 PFLOPS＝1 EFLOPS。算力换算不改变FP16精度口径，不等于可用训练吞吐量。
- 现金流出保存负号。“经营现金流减现金购建”在脚本中表现为两项带符号金额相加；它不是跨公司统一自由现金流，也未覆盖全部非现金资产取得。
- 不做汇率换算，不把美元、人民币相加。财年、自然年、年末时点和预测期分别记录。
- 全部数据中心与AI数据中心、设施面积利用率与GPU利用率、集团收入与纯AI收入、RPO与backlog必须分开。
- 公开财报与公司宣传的证据用途不同；来源为官方也不能消除样本、定义、未经审计或预测的不确定性。


## 3. 专题分析问题结构

每个产业专题的研究阶段须覆盖下列问题；章节可以合并，交付检查时应能在研究底稿中定位到具体答案、数据或“不适用”的依据。报告按主问题与论证顺序组织，不要求将全部研究维度逐项列成正文章节。

| 分析维度 | 必须回答的问题 |
|---|---|
| 边界与产业位置 | 研究对象的产品、服务、法律主体、资产和地域边界是什么；处在产业链哪一层，与上下游如何结算 |
| 市场与产业经济性 | 全球及中国结构、需求驱动、供给约束、竞争与替代、价格形成、政策影响、壁垒和变化方向是什么 |
| 项目与合同 | 谁投资、持有、建设、供给、采购、使用和付款；容量／数量、工期、交付验收、定价、结算及违约风险如何分配 |
| 财务与信用 | 收入、成本、利润、营运资金、资本开支、现金流、债务、租赁、担保抵押及期限错配如何形成信用风险 |
| 情景与反证 | 基准、压力及关键敏感性如何改变现金流和偿债能力；最重要的反证、口径限制和待核材料是什么 |
| 银行切入 | 结算、现金管理、融资和非融资信用需求出现在哪个时点；服务主体、准入、交易真实性、还款来源和风险承担是什么 |
| 横向接口 | 与其他产业层、P1关系图、中国／海外口径和后续尽调任务如何衔接；用什么指标持续验证判断 |


## 4. P2专题必提字段与交付底线

P2包含八个产业单元、一个行业需求侧专题和一个横向核查任务，共10项任务；不得把“其余九项任务”均称为产业单元。

### P2统一交付要求（Energy Review反馈）

1. 每个研究专题至少包含一个中国企业样本和一个中国项目／交易样本，并明确法律主体、业务、财务或投资事实及来源；两者可以有关联，但集团数据不得替代项目数据。横向核查任务P2-10验证已有样本覆盖，不要求重复造案例。字段未取得时列已查材料、影响和下一步；缺少中国样本不得标完成。
2. 教学模型先定义借款主体、资产范围、收入来源及成本承担，再设投资、债务和现金瀑布。单位造价、容量和收入规模与P1/P2已有数据交叉校验，列明币种、资产范围和差异原因；不为对齐而强行换汇。区分电价转付、包干和传导滞后。CFADS不足本息时同时报告年度现金缺口；CFADS为负不呈现负DSCR，不把教学假设当行业预测。
3. 每张用于分析的数据表，应在研究底稿或随表说明中记录其支持的判断与适用限制；把到期与爬坡、订单与交付、收入与回款等相关数字放在同一时间轴解释。报告只选用支持主要论点的表格，重点解释关键差异；完整来源索引、字段清单和重复口径说明留在底稿或附录，直接影响结论的限制随论点保留。
4. 研究交付时逐项勾选以下12环节并写研究底稿定位：业务边界、全球结构与中美差异、需求供给、竞争替代、收入成本资本现金流、合同质量、资金需求融资抵押及风险承担、银行服务及切入时点、壁垒、层间接口、变化与验证指标、来源及未决问题。缺失项补齐，确实不适用须说明依据。检查结果放在 REVIEW 或实施与验收记录中，作为研究覆盖检查，不直接作为报告目录或正文。
5. 完成度按“任务数×版本状态”汇报，并分别列首版、修订中、已验收、未启动；例如“P2：1/10首版、0/10验收”。版本号不等于验收结论。公开不可得的合同可带具体接收任务转办；验收前置条件不能仅转办后宣称关闭。

以上要求在启动Chip前生效，后续专题沿用。

### P2参数、证据与验收操作规则（Energy复评审反馈）

1. **核心参数锚。** 对价格、单位造价、容量、利用率、合同期限、回款期和融资条件等会影响结论的参数，逐项记录数值、数据ID／来源、期间、地域、税费及资产边界；无公开锚点时明确标为教学假设。基准情景优先采用当前可得的公开市场或监管锚点，原假设只能作为注明口径的对照或敏感性。交叉样本边界不同时，不得声称直接验证，应写明高低方向、形成该方向的边界差异及其对模型的方向性信号。
2. **价格分层与可比性。** 发电／合同价、代理购电或市场购电价、线损、输配电度价、系统运行费、政府性基金附加、需量／容量费分别列示。区间比较原则上做到同月、同电网、同电压等级、同计费类别；需量和容量两种计费不得同时计入。1439号文后的省级电网代理购电表可作普通网购电用户终端价参照，但须标注“代理购电口径，非直连或市场化用户实缴价”，不得据此声称688／1192项目或绿电直连项目的实际电价。模型参数须反向链接到正式数据ID。
3. **合同与负荷风险。** 转付、包干和传导滞后至少各有可识别的合同机制或情景；按适用性测试转付上限、PUE上限、回款滞后、空置容量费、负荷／出租率下降及需量／容量计费选择。容量费是否随在租比例承担须明示，不得默认剩余客户承担全部空置容量费；可以申请减容或改按需量计费时，列为缓释条件而非既成事实。
4. **项目样本交易链。** 中国项目／交易样本除投资额和规模外，尽量识别项目公司或借款人、资产持有方、建设方、供给／售电方、负荷／采购方、付款方、电网接入或交付验收、定价结算、融资及担保。关键一环未取得时，三态记录已查材料、对结论的影响和下一步；样本只能证明园区或负荷侧时，应在验收记录中写明样本强弱，不能把它表述为完整能源侧或交易闭环样本。
5. **编号与文档一致性。** 同一事实只保留一个正式指标ID；重编号须保留旧号到新号的明确映射，不得留下倒序、交叉或与其他数据段重叠的编号范围。文档验证覆盖专题目录、数据目录及评审目录中的全部活跃Markdown，并检查正文引用、字段表、证据稿、README、验收记录与模型输出是否一致；历史归档文件须明确标注，避免被当作现行证据。
6. **原始数据与可复现性。** 原始输入、归一结果和衍生指标分开保存；数据包由脚本生成时，不直接手工改生成文件。交付前从原始输入重新生成，并核对场景数、指标数、关键公式、文件哈希或等效一致性检查。进出口结论优先使用海关或UN Comtrade等原始查询，保存HS编码、贸易伙伴、金额、数量、法定计量单位和查询条件，明确排除的相邻税号；媒体转引只作线索。
7. **统一验收门槛。** 每次修订在实施记录中列出验收前置条件与非阻塞跟踪项，以评审原文和经确认的工作步骤为唯一门槛来源；两者冲突时先更正步骤文件并记录理由。转办项须有编号、接收专题和所需材料，不能阻塞项与跟踪项混报。勾选验收前须从原始输入重新生成并运行数据、模型、编号、链接和全部活跃文档的新鲜验证；弱样本、仍未取得的事实和结论边界须随验收保留。

每家用于支撑关键判断的样本，建立“已披露并提取／未单独披露／未取得”三态清单。未取得须写查过的章节、缺口影响、下一步材料，不能只以免责声明代替提取。

## 5. 补强中形成的口径约定

1. 审计状态落到指标，不把年报里的面积、backlog、调整后EBITDA及计划统一标为“审计值”。
2. 到期表完整后也须匹配CFADS期间和主体才计算DSCR；历史CFO/次年本金称静态压力观察。US GAAP CFO中的现金付息避免重复扣减。
3. 关系记录必须含方向、类别、金额/未披露、现金状态、会计处理/待核、期间、证据来源与具体缺失材料。
4. 价格必须含配置、精度、地区、计费、税、折扣、查阅日；预留价未公开则明确询价，不能把按需折算成合同报价。公司示意建设预算与实际结算成本分开。
5. 国资平台至少分控股母公司、资产持有方、运营方、最终付款人。算力券按合同及核销实质区分客户对价、补助或代付；政府出资与有效保证责任分开。
6. 同日工作用修订序号表示可核顺序，不追补未经记录的时间戳。原始文件、数据与更正桥保留在历史目录。
