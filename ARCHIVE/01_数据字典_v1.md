## 1. 数据总体架构

采用四层结构，原始层只增不改，分析层可重建：

```
原始层 raw      公告 PDF、网页快照、Tushare 原始返回、政策原文
   ↓ 清洗
暂存层 staging  统一字段、去重、单位换算、缺失标记
   ↓ 关联
核心层 core     企业、机构、工具、融资事件、服务关系、财务、供应链
   ↓ 聚合
分析层 mart     指标宽表、模式矩阵、案例卡片、图表数据
```

**原则**：

1. 任何进入核心层的记录，必须能回溯到原始文件或 URL；
2. 原始层保留抓取时间与来源，不覆盖历史版本；
3. 清洗规则写入脚本，不手工改数；
4. 缺失值统一标记为 `NULL`，并记录缺失原因，不用 0 代替。

## 2. Tushare 接入

### 2.1 Token 读取

Token 存放于 `_secrets/tushare_token.txt`，一行文本，UTF-8 无 BOM。脚本只从文件读取，不硬编码、不写入日志。

```python
from pathlib import Path
import tushare as ts

TOKEN = Path("_secrets/tushare_token.txt").read_text(encoding="utf-8").strip()
pro = ts.pro_api(TOKEN)
```

### 2.2 权限探测（接入后第一件事）

Tushare 按积分分级开放接口，不同账号权限差异较大。接入后先跑一次探测，输出"可用/不可用/限频"清单，再决定哪些字段走接口、哪些走抓取。

探测步骤：

1. 调用 `stock_basic` 确认 Token 有效；
2. 逐个调用下表接口，记录：是否返回、返回行数、字段名、报错信息；
3. 对每个可用接口做一次小样本拉取（如 1 只股票、近 3 年），确认字段口径；
4. 记录单次调用行数上限与每分钟频率限制；
5. 结果写入 `20_数据库/tushare_capability.json`。

### 2.3 接口清单（接口名与权限以探测结果为准）

**注意**：

- 接口名称、字段名以实际返回为准，本文档在探测后更新为 v1.1；
- 部分接口需要较高积分，若不可用，改用巨潮/交易所抓取，不阻塞整体进度；
- 批量拉取必须本地缓存（Parquet 或 SQLite），避免重复消耗积分；
- 拉取脚本需限频、重试、断点续传。

## 4. 数据库表设计（SQLite）

```sql
-- 1. 企业维表
CREATE TABLE dim_company (
  company_id      TEXT PRIMARY KEY,      -- 自定义短码，如 BYD
  name            TEXT NOT NULL,
  ts_code         TEXT,                  -- 002594.SZ
  hk_code         TEXT,                  -- 01211.HK
  industry        TEXT,
  ownership       TEXT,                  -- 民营/国有/外资/公众
  listing         TEXT,                  -- A/H/A+H
  rd_intensity    REAL,
  chain_role      TEXT,                  -- 链主类型
  note            TEXT
);

-- 2. 机构维表
CREATE TABLE dim_institution (
  inst_id         TEXT PRIMARY KEY,
  name            TEXT NOT NULL,
  inst_type       TEXT,                  -- 银行/券商/保险/信托/租赁/保理/基金/平台/担保
  group_name      TEXT,                  -- 所属集团
  licenses        TEXT,                  -- 逗号分隔的牌照
  listed          INTEGER,
  ts_code         TEXT,
  note            TEXT
);

-- 3. 工具维表
CREATE TABLE dim_tool (
  tool_id         TEXT PRIMARY KEY,
  name            TEXT NOT NULL,
  chain           TEXT,                  -- capital/funding/supply
  category        TEXT,                  -- 股权/债权/交易信用/担保保险/平台
  description     TEXT
);

-- 4. 融资事件事实表
CREATE TABLE fact_financing_event (
  event_id        TEXT PRIMARY KEY,
  company_id      TEXT REFERENCES dim_company(company_id),
  event_date      TEXT,                  -- YYYY-MM-DD
  tool_id         TEXT REFERENCES dim_tool(tool_id),
  amount          REAL,
  currency        TEXT,
  maturity_years  REAL,
  coupon_rate     REAL,
  lead_inst_id    TEXT REFERENCES dim_institution(inst_id),
  other_insts     TEXT,
  source_url      TEXT,
  source_type     TEXT,                  -- 年报/募集说明书/公告/ABS/评级报告
  evidence_level  TEXT,                  -- A/B/C/D
  raw_file        TEXT,
  note            TEXT
);

-- 5. 服务关系事实表（核心）
CREATE TABLE fact_service_relation (
  relation_id     TEXT PRIMARY KEY,
  company_id      TEXT REFERENCES dim_company(company_id),
  inst_id         TEXT REFERENCES dim_institution(inst_id),
  tool_id         TEXT REFERENCES dim_tool(tool_id),
  year            INTEGER,
  role            TEXT,                  -- 保荐/主承/受托/授信/计划管理/评级/担保/托管
  cross_license   INTEGER,               -- 0/1，是否跨牌照协同
  consecutive_years INTEGER,             -- 连续服务年限
  evidence_level  TEXT,
  source_url      TEXT
);

-- 6. 财务指标事实表
CREATE TABLE fact_financial (
  company_id      TEXT REFERENCES dim_company(company_id),
  period          TEXT,                  -- 2023-12-31
  revenue         REAL,
  operating_cost  REAL,
  net_profit      REAL,
  rd_expense      REAL,
  total_assets    REAL,
  interest_expense REAL,
  short_debt      REAL,
  current_portion_ltd REAL,
  long_debt       REAL,
  bond_payable    REAL,
  lease_liability REAL,
  ar              REAL,
  ap              REAL,
  inventory       REAL,
  ocf             REAL,
  gov_subsidy     REAL,
  source          TEXT,
  PRIMARY KEY (company_id, period)
);

-- 7. 供应链金融事实表
CREATE TABLE fact_supplychain (
  id              TEXT PRIMARY KEY,
  company_id      TEXT REFERENCES dim_company(company_id),
  year            INTEGER,
  platform_name   TEXT,
  instrument      TEXT,                  -- 数字凭证/保理/ABS/票据/订单融资
  volume          REAL,                  -- 交易或融资规模
  tier_depth      INTEGER,               -- 凭证流转层级
  supplier_count  INTEGER,
  source_url      TEXT,
  evidence_level  TEXT
);

-- 8. 政策维表
CREATE TABLE dim_policy (
  policy_id       TEXT PRIMARY KEY,
  title           TEXT,
  issuer          TEXT,
  doc_no          TEXT,
  publish_date    TEXT,
  effective_date  TEXT,
  chain           TEXT,                  -- capital/funding/supply/all
  summary         TEXT,
  url             TEXT,
  verified        INTEGER DEFAULT 0      -- 0 待核校，1 已核校
);

-- 9. 文献维表
CREATE TABLE dim_literature (
  lit_id          TEXT PRIMARY KEY,
  authors         TEXT,
  year            INTEGER,
  title           TEXT,
  journal         TEXT,
  theory          TEXT,
  method          TEXT,
  findings        TEXT,
  relevance       INTEGER,               -- 1-5
  file_path       TEXT
);

-- 10. 编码表
CREATE TABLE coding (
  code_id         TEXT PRIMARY KEY,
  company_id      TEXT REFERENCES dim_company(company_id),
  source_url      TEXT,
  quote           TEXT,
  first_order     TEXT,
  second_order    TEXT,
  mechanism       TEXT,
  proposition     TEXT,
  coder           TEXT,
  coded_at        TEXT,
  confidence      TEXT                   -- high/medium/low
);
```

**索引建议**：

```sql
CREATE INDEX idx_event_company ON fact_financing_event(company_id, event_date);
CREATE INDEX idx_relation_company ON fact_service_relation(company_id, year);
CREATE INDEX idx_relation_inst ON fact_service_relation(inst_id, year);
CREATE INDEX idx_fin_period ON fact_financial(company_id, period);
CREATE INDEX idx_sc_company ON fact_supplychain(company_id, year);
```

## 5. 指标计算口径

### 5.1 资本链

| 指标 | 公式 | 口径说明 |
|---|---|---|
| 股权融资占比 | 股权融资额 /（股权融资额 + 有息负债增加额） | 按年度流量计算 |
| 研发强度 | 研发费用 / 营业收入 | 研发费用取利润表"研发费用"科目 |
| 研发资本化率 | 本期开发支出增加额 / 研发投入合计 | 需从研发投入附注取数 |
| 机构投资者持股比例 | 基金、保险、QFII、社保合计持股 / 总股本 | 取年报或 Tushare 股东数据 |
| 并购强度 | 年度并购交易金额 / 总资产 | 交易金额含现金与股份对价 |
| 政府补助依赖 | 政府补助 / 利润总额 | 利润总额为负时不计算，标注"不适用" |

### 5.2 资金链

| 指标 | 公式 | 口径说明 |
|---|---|---|
| 有息负债 | 短期借款 + 一年内到期的非流动负债 + 长期借款 + 应付债券 + 租赁负债 | 不含应付账款等经营性负债 |
| 综合融资成本 | 利息支出 / 平均有息负债 | 平均 =（期初 + 期末）/ 2；利息支出从财务费用附注取 |
| 长期负债占比 | （长期借款 + 应付债券 + 租赁负债）/ 有息负债 | — |
| 现金转换周期 | 存货周转天数 + 应收账款周转天数 − 应付账款周转天数 | 天数按 365 计 |
| 存货周转天数 | 365 × 平均存货 / 营业成本 | — |
| 应收账款周转天数 | 365 × 平均应收账款 / 营业收入 | 应收账款含应收票据时需注明 |
| 应付账款周转天数 | 365 × 平均应付账款 / 营业成本 | — |
| 利息保障倍数 | EBIT / 利息费用 | EBIT = 利润总额 + 利息费用 |

### 5.3 供应链

| 指标 | 公式 | 口径说明 |
|---|---|---|
| 供应商集中度 | 前五大供应商采购额 / 采购总额 | 年报"主要供应商"披露 |
| 客户集中度 | 前五大客户销售额 / 营业收入 | 年报"主要客户"披露 |
| 供应链金融渗透率 | 供应链金融融资余额 / 应付账款余额 | 需平台或ABS披露，缺失时标注 |
| 凭证流转层级 | 数字债权凭证可流转的最多级数 | 平台披露或研报 |

### 5.4 综合经营

| 指标 | 公式 | 口径说明 |
|---|---|---|
| 牌照覆盖数 | 机构持有的金融牌照类型数 | 按银行、证券、保险、信托、租赁、保理、基金、小贷、支付、征信计 |
| 产品交叉数 | 同一客户使用的产品类别数 | 从服务关系表按企业—机构聚合 |
| 连续服务年限 | 机构连续提供服务的年数 | 允许间隔 1 年 |
| 跨牌照协同率 | 存在跨牌照协同的关系数 / 总关系数 | 以 `cross_license=1` 计 |

**通用规则**：

- 所有金额统一为人民币万元，外币按年末中间价折算；
- 比率保留 4 位小数，展示时保留 2 位；
- 缺失值不插补，不用 0，不做前后向填充；
- 口径变更写入版本记录，历史数据不覆盖。

## 6. 证据强度分级

| 等级 | 来源 | 使用规则 |
|---|---|---|
| **A** | 监管披露、审计报告、募集说明书、法律意见书、交易所公告 | 可作为核心论断的直接证据 |
| **B** | 机构年报、官网、评级报告、行业协会统计、学术论文 | 可支撑背景与机制判断 |
| **C** | 券商研报、权威财经媒体、企业新闻稿 | 仅作线索，需 A/B 级佐证 |
| **D** | 一般媒体、自媒体、论坛 | 不作为证据，只用于发现线索 |

**规则**：

- 每条核心论断至少 1 条 A 级，或 2 条相互独立的 B 级；
- C 级材料引用时标注"据媒体报道"，不写成事实；
- D 级材料进入 `90_过程记录/线索池.md`，不进入正文；
- 同一事实有冲突时，以监管披露为准，并在脚注说明差异。

## 8. 质量控制与版本管理

| 环节 | 措施 |
|---|---|
| 抓取 | 保存 URL、抓取时间、文件哈希；失败重试 3 次并记录 |
| 录入 | 双人录入关键字段；单人时 48 小时后复核 |
| 清洗 | 规则脚本化，变更留痕；不手工改核心层 |
| 核对 | 抽样 10% 回查原文；金额、日期、机构名逐字核对 |
| 版本 | 数据库文件按 `YYYYMMDD` 备份；文档用 v1.0/v1.1 递增 |
| 审计 | 每月输出一次"数据质量报告"：缺失率、重复率、来源分布 |
