## 0. 研究与报告分阶段

研究目标与范围由 [`00_研究框架_v2.3.md`](00_研究框架_v2.3.md) 维护；成稿的写作规则见 [`06_写作规范_v0.2.md`](06_写作规范_v0.2.md)。

### 0.1 研究阶段

研究阶段优先收集、验证与整理数据和案例，形成**有来源、有口径、有解释、有反证、有待补证据**的研究底稿。原始资料、数据台账和模型放在 `20_数据库/`、`14_原始公告/`、`12_企业档案/`、`13_机构档案/`；专题底稿放在 `30_编码/`；过程性记录放在 `90_过程记录/`。

**字段完整性和证据追溯性优先，不为成稿形式删减原始材料。** 底稿可以长、可以杂、可以保留冲突；报告才需要精炼。

### 0.2 报告阶段

报告阶段使用**已核验材料**，围绕主问题组织"判断—证据—解释—含义"，执行写作规范。成稿放在 `50_稿件/`；通过证据卡编号引用底稿，保留关键数字与判断条件。发现影响结论的新证据缺口时，**回到研究阶段补证**，不在报告里直接补事实。

### 0.3 两类验收，分别记录

| 验收类型 | 检查什么 | 记录位置 |
|---|---|---|
| **研究验收** | 证据、案例、数据、覆盖完整性、待补清单 | `90_过程记录/研究验收.md` |
| **成稿验收** | 论证、可读性、重点呈现、改写后的事实保真 | `90_过程记录/成稿验收.md` |

**研究验收通过，不自动代表成稿通过。** 两类检查分别记录，不能互相替代。

### 0.4 本项目目录映射

| 参考规范目录 | 本项目目录 | 内容 |
|---|---|---|
| 数据/ | `20_数据库/`、`14_原始公告/` | 原始数据、公告快照、数据台账 |
| 专题/ | `30_编码/` | 证据卡、案例卡片、编码表 |
| REVIEW | `90_过程记录/` | 检索日志、复核记录、验收记录 |
| 报告/ | `50_稿件/` | 报告各版本 |

## 1. 证据规范

1. **来源优先级**：优先采用财报、监管披露、交易所公告、官方统计、评级报告、有明确方法的行业研究；券商研报和媒体只作线索。
2. **公司自述的边界**：公司对自身产品、业务、客户的披露可用于核实经营数据；但其市场地位、协同效果、技术领先等宣传，必须独立交叉验证。**银行年报/新闻稿对"协同"的自述，不能单独作为协同证据。**
3. **来源要素**：每项关键数据记录来源链接、发布日期、观测期、地域、单位、定义及必要限制；缺一不可。
4. **事实类型**：明确标注事实、估算、预测、分析判断、待验证假设；报告中不得把估算写成披露。
5. **口径拆分**：区分集团与上市公司、合并与母公司、总收入与分部收入、存量与流量、承诺与投放、签约与交付、授信与提款。
6. **缺失不为零**：数据缺失记为 `null` 或"未披露"，不填 0，不用行业均值替代。
7. **会计差异**：跨公司比较财务指标前，记录折旧政策、研发资本化、租赁、票据贴现、结构化安排的差异；口径不可比时不做横向比较。
8. **关联与融资**：分别标注关联关系、供应商融资、交叉投资、资金依赖；不把融资安排自动等同于收入虚假，也不把关联交易自动等同于真实需求。
9. **历史类比**：使用历史类比时，说明可比与不可比之处，不直接套用结论。
10. **公开研究 vs 尽调**：区分"公开资料可得出的结论"与"需要尽调核实的事项"；合同原件、流水、债务到期表、担保及抵质押登记列为补充材料，并写明每项材料用于验证什么判断。
11. **银行产品匹配**：须考虑具体服务主体、业务资格、区域与客户准入、交易真实性、本行能力；通用研究不替代具体授信审批或产品可开展性核实。
12. **不称"回测"**：公司案例用于框架适用性验证；缺乏历史样本、评价时点和实际结果时，不称"回测"。
13. **A/B 类分离**：银行并表子公司协同（A 类）与集团兄弟公司协同（B 类）必须分开取证、分开表述；不得把兄弟公司服务写成银行子公司服务。
14. **来源独立性**：银行通稿及其转载，合计只算一份来源；同一事实需要两条以上独立来源时，不能拿通稿+转载充数。
15. **绩效数字**：用区间 + 方向性表述；不做跨行排名、不做点估计、不做因果归因；具体见第 6 节与写作规范。
16. **中车边界**：中国中车集团发债与上市公司担保是两件事；不得把集团债券算到上市公司，也不得把上市公司担保额算成集团负债。

## 2. 数据字段与换算

### 2.1 原始指标字段

| 字段 | 说明 |
|---|---|
| `id` | D 编号，唯一 |
| `source_id` | 来源编号，关联来源表 |
| `entity` | 主体（企业/银行/法人） |
| `metric` | 指标名 |
| `period` | 期间（YYYY、YYYYQN、YYYY-MM-DD） |
| `raw_value` | 原始数值，**用字符串**，避免浮点误差 |
| `raw_unit` | 原始单位 |
| `status` | 已披露并提取 / 未单独披露 / 未取得 / 不适用 |
| `scope` | 合并/母公司、集团/上市公司、地域 |
| `locator` | 页码、章节、表格、URL 锚点 |
| `notes` | 口径、限制、异常 |
| `normalization_multiplier` | 换算因子 |
| `normalized_unit` | 归一单位 |
| `currency` | 币种 |

**归一值 = 原值 × 换算因子；衍生指标另存 `input_ids`、`formula`、`source_ids`，不覆盖原值。**

### 2.2 来源字段

| 字段 | 说明 |
|---|---|
| `source_id` | 来源编号 |
| `publisher` | 发布主体 |
| `title` | 标题 |
| `url` | 链接 |
| `publication_date` | 发布日期；只有年份的保留年份 |
| `coverage` | 覆盖期间/范围 |
| `source_type` | 公告/年报/监管/研报/媒体/学术 |
| `limitations` | 限制 |
| `accessed_on` | 查阅日 |
| `access_status` | 可访问/付费墙/已失效 |

**查阅日 ≠ 发布日期 ≠ 统计期。**

### 2.3 关系字段

| 字段 | 说明 |
|---|---|
| `edge_id` | 关系编号 |
| `from` / `to` | 企业/银行/法人 |
| `relationship` | 授信/承销/担保/托管/投资/租赁/保理等 |
| `amount_metric_id` | 金额指标 ID；未提取填 `null` |
| `source_ids` | 来源编号列表 |
| `period` | 期间 |
| `evidence_level` | A/B/C/D |
| `limitations` | 限制 |

**金额 `null` = 本次未提取到可归属金额，不是零。** 筹资净额不能分配给单一投资者；战略联系不画成实际资金流。

### 2.4 单位与边界

- 人民币百万元 × 0.01 = 亿元；
- 人民币千元 × 0.00001 = 亿元；
- 人民币元 × 0.00000001 = 亿元；
- **不做汇率换算，不把人民币与港币/美元相加**；H 股公司如以人民币披露，注明币种；如以港币披露，单独列示，不混算；
- 财年、自然年、年末时点、预测期分别记录；
- 集团与上市公司、总收入与分部收入、存量与流量、承诺与投放必须分开；
- 授信额度、已用额度、提款额、担保余额分别记录。

## 3. 三态清单与共性字段

### 3.1 三态清单

每家样本企业、每家银行，建立"已披露并提取 / 未单独披露 / 未取得"三态清单。

| 状态 | 含义 | 记录要求 |
|---|---|---|
| 已披露并提取 | 原文有，已录入证据卡 | 给编号、页码/URL、口径 |
| 未单独披露 | 合并披露，无法拆分 | 写明合并口径、影响 |
| 未取得 | 公开资料没有 | 写明查过的章节、缺口影响、下一步材料 |

**未取得不能只写"未披露"了事；必须写"查过什么、缺什么、影响哪个判断、下一步找什么"。**

### 3.2 共性字段

每个用于支撑关键判断的样本，至少覆盖：

| 类别 | 字段 |
|---|---|
| 主体边界 | 法律主体、业务边界、上市地、集团归属、并表范围 |
| 经营 | 收入、分部收入成本利润、抵消、毛利率、研发投入/费用、资本化率 |
| 现金流 | 现金购建、非现金新增、CFO、营运资金变动、现金及受限现金 |
| 债务 | 有息债务本金/账面、当期到期、逐年摊还、现金利息与损益利息、租赁及未起租承诺 |
| 上下游 | 客户/供应商集中度、合同期限、取消/退款条款、账期 |
| 资产 | 权属、抵押担保、追索安排 |
| 融资 | 融资模式自述、定位、授信与提款、债券与担保 |
| 银行关系 | 银行集团、法人、结构类型 A/B、工具、角色、年份、证据编号 |
| 供应链金融 | 财务公司、保理、租赁、平台、数字凭证、ABS |
| 判断边界 | 反证、口径限制、待核材料 |

## 4. 底稿规范

### 4.1 底稿类型与编号

| 类型 | 前缀 | 用途 | 示例 |
|---|---|---|---|
| 企业底稿 | E | 公告、年报、募集说明书、担保、债券 | E-300750-20260928-001 |
| 银行底稿 | B | 银行年报、公告、AIC、监管批复 | B-CMB-20260328-001 |
| 政策底稿 | P | 政策原文、监管文件 | P-PBOC-20250507-001 |
| 文献底稿 | L | 论文、研究报告 | L-2024-001 |
| 数据底稿 | D | Tushare、统计、财务指标 | D-002594-2025-001 |
| 编码底稿 | C | 编码表、矩阵、判断依据 | C-W8-001 |
| 检索日志 | S | 检索式、结果数、筛选理由 | S-20261112-001 |

编号规则：`{前缀}-{主体/主题}-{YYYYMMDD}-{三位序号}`；一经分配，不再复用。

### 4.2 证据卡字段

| 字段 | 要求 |
|---|---|
| 编号 | 按 4.1 |
| 事实摘要 | ≤50 字 |
| 事实类型 | 事实 / 估算 / 预测 / 判断 / 待验证假设 |
| 原文摘录 | 逐字；不改错别字；超 200 字截取关键段并注明上下文 |
| 来源 | 文件名/URL；公告写全称 |
| 发布主体/日期 | 公司/银行/监管；发布日期 |
| 口径/期间/单位 | 金额、比例、年份 |
| 证据等级 | A/B/C/D |
| 来源独立性 | 独立 / 转载 / 银行自述 |
| 关联链条 | 资本链 / 资金链 / 供应链 |
| 关联主体 | 企业、银行集团、法人 |
| 三态 | 已披露并提取 / 未单独披露 / 未取得 |
| 核校状态 | 待核 / 已核 / 冲突 |
| 提取人/日期 | 谁、何时 |
| 备注 | 疑点、冲突、待补 |

### 4.3 底稿质量

- 原文优先；能截图不手抄；
- 一卡一事实；
- 不改原文，解释放"备注"；
- 冲突保留，两张卡都留；
- 待核标记【待核校】；
- 从报告任意一句事实，1 分钟内能找到证据卡和原文。

### 4.4 底稿锁定

- 每家/每家银行完成后打"锁定"；
- 锁定后修改，新增"修订卡"，注明原因、修订人、日期；
- 锁定版本存 `30_编码/底稿/`，不覆盖旧版。

## 5. 数据留底

### 5.1 分层

```
raw（原始层） → staging（暂存层） → core（核心层） → mart（分析层）
```

### 5.2 留底内容

| 数据类型 | 留底内容 | 存放位置 |
|---|---|---|
| Tushare | 接口名、参数、时间、JSON/CSV、行数、错误 | `20_数据库/raw/tushare/` |
| 巨潮/交易所 | PDF/HTML、URL、抓取时间、哈希 | `14_原始公告/` |
| 银行年报 | PDF、页码、章节 | `13_机构档案/` |
| 手工录入 | 原始截图、录入人、复核人 | `30_编码/录入/` |
| 证据卡 | Markdown/CSV | `30_编码/证据卡/` |
| 编码表 | Excel/CSV | `30_编码/` |
| 报告 | Markdown/Word/PDF | `50_稿件/` |

### 5.3 命名

```
{来源}_{主体}_{YYYYMMDD}_{类型}_{序号}.{ext}
```

示例：`TUSHARE_002594.SZ_20261112_income.json`、`CNINFO_300750_20260928_债券发行完成公告.pdf`。

### 5.4 不覆盖与备份

- 原始文件只增不改；清洗另存；
- 数据库按 `YYYYMMDD` 备份；
- 文档用 `vX.Y` 递增，旧版保留并标注"已被取代"；
- 每月备份到外部盘；PDF 与大数据不入版本库；
- 密钥只在 `_secrets/`。

## 6. 证据等级与来源独立性

| 等级 | 来源 | 使用 |
|---|---|---|
| A | 监管披露、审计报告、募集说明书、法律意见书、交易所公告、监管批复 | 核心论断的直接证据 |
| B | 银行年报、官网、评级报告、行业协会统计、学术论文 | 背景与机制判断 |
| C | 券商研报、权威财经媒体、企业新闻稿 | 仅作线索，需 A/B 佐证 |
| D | 一般媒体、自媒体、论坛 | 只用于发现线索 |

**规则**：

- 核心事实至少 1 条 A，或 2 条相互独立的 B；
- 银行通稿及转载合计 1 份；
- C 级引用标注"据媒体报道"；
- D 级进 `90_过程记录/线索池.md`，不进报告；
- 冲突时以监管披露为准，脚注说明差异。

## 7. 事实核校

逐字核对：

- 政策：机关、文号、发布日期、施行日期、有效性；
- 持股：股东名称、比例、截止日、并表范围；
- 金额：币种、单位、口径、含税与否；
- 机构：全称、简称、集团归属、法人边界；
- 时间：事件日、公告日、数据截止日。

每条【待核校】必须有"核校人、日期、来源"；核校不通过改为"证据不足"，不强行写。

## 8. 质量复核与验收

### 8.1 复核

| 环节 | 做法 |
|---|---|
| 底稿复核 | 完成后 48 小时内；单人研究隔日复核 |
| 抽样回查 | 随机 10% 证据卡回查原文 |
| 编码复核 | 编码表完成后一周；关键编码双人核对 |
| 数字复核 | 报告数字与数据底稿逐项比对 |
| 引文复核 | 政策文号、公告名称、机构全称逐字核对 |

### 8.2 研究验收清单

- [ ] 证据卡覆盖主样本与对照样本；
- [ ] 三态清单完整，未取得项写清查过什么、影响、下一步；
- [ ] A/B 类结构未混写；
- [ ] 绩效数字有口径、期间、来源；
- [ ] 待核事项有清单；
- [ ] 数据留底可回溯。

### 8.3 成稿验收清单

- [ ] 主判断可检验，标题/开头/加粗能连成主线；
- [ ] 每个事实句有证据编号；
- [ ] 事实、解释、假设分开；
- [ ] 没有跨行排名、没有因果归因；
- [ ] 关键数字有对比基准和含义；
- [ ] 读者测试通过（只读标题、开头、加粗，能复述主线）。

**两类验收分别记录，研究验收通过不等于成稿通过。**

## 9. 伦理与保密

- 只用公开信息；不使用银行内部授信政策、客户名单、定价数据；
- 不把银行通稿当独立证据；
- 涉及具体银行的评价性表述，按刊物要求决定真名或匿名；
- 密钥只存 `_secrets/`；
- 发现数据泄露风险，立即停止使用并报告。

## 11. 本项目特有规则

1. **银行侧正推为主，企业侧反推为辅**；企业是需求窗口。
2. **A/B 类分开**：并表子公司 vs 集团兄弟公司。
3. **样本**：主样本 5 家（比亚迪、宁德时代、中国中车、京东方、三一重工）+ 例外对照 3 家（立讯精密、美的集团、海尔智家）；对照组不进模式归纳。
4. **绩效**：区间 + 方向性；不排名、不点估计、不因果归因。
5. **不做访谈**；协同机制判断至少两份独立公开来源。
6. **银行名称**：真名/匿名待刊物要求；评价性表述优先"某股份行"。
7. **小米不纳入**；不获取港股数据。
8. **中车边界**：集团发债 ≠ 上市公司负债；上市公司担保 ≠ 集团担保。
9. **研发门槛**：优先 ≥5%；3.0%–5.0% 且绝对研发 ≥100 亿元可作例外对照；以年报"研发投入合计"复核。
